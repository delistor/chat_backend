0.3 三份蓝图各自的「一句话灵魂」

Claude Code：单体即性能
一个 2057 行的 async generator 循环装下一切；所有外围（hooks/skills/MCP/插件）都是这个循环的正交扩展点。设计目标是交互延迟与缓存命中——流式期间就开跑工具、fork 共享父缓存、附件只在尾部追加。适合学「怎么把一个循环做到工业级」。
OpenClaw：网关即产品
核心是一个常驻 Gateway（单端口 WS+HTTP，18789）接管所有消息渠道；agent 只是它调度的资源之一。设计目标是7×24 常驻、多渠道、多 agent 路由——会话键语法、dmScope 隔离、cron/heartbeat 都是围绕「消息从哪来、回到哪去」。适合学「怎么把 agent 做成在线服务」。
dsh：组合即数据
内核只有「插件容器 + 事件溯源会话」两样；整个产品是一叠 YAML 补丁组合出来的（bundle→profile→home→overlay），甚至有一个 preset 让模型自己写 TS 程序代替逐个调工具。设计目标是可组合、可重放、可自改。适合学「怎么把框架做成平台」。

D1 · 终极对比：三种架构哲学

Claude Code：单体循环
组织方式：一个 async generator 循环装下一切，外围全是扩展点。优化目标：交互延迟与缓存命中（流式开跑工具、fork 共享父缓存、附件尾部追加）。信任模型：单用户本地工具，权限靠判定链+人工确认。复杂度去处：错误恢复（10 种终止原因、降级/放宽/恢复消息/紧急压缩）。
OpenClaw：常驻网关
组织方式：Gateway 接管一切消息面，agent 是被调度的资源。优化目标：7×24 常驻、多渠道路由、多 agent 隔离。信任模型：消息来自外部世界——设备配对、challenge 签名、幂等键、五层权限。复杂度去处：会话键语法与 dmScope 隔离、writer-claim 防竞态、cron/heartbeat。
dsh：组合平台
组织方式：微内核（插件容器+事件溯源），产品=一叠 YAML。优化目标：可组合、可重放、可自改（cordis preset 让 agent 改自己的组合）。信任模型：preset 即信任边界（minimal/standard/cordis 三档）。复杂度去处：双平面归属规则（host/agent）、投影一致性、KV-cache 纪律。

一句话：Claude Code 把循环做到极致，OpenClaw 把网关做到极致，dsh 把组合做到极致。你要抄哪一家，取决于你的产品形态是「工具」「服务」还是「平台」。
