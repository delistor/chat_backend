外置智能体记忆：何时触发、如何召回

Hermes Agent（Nous Research）记忆架构 × 主流外置记忆方案 · 一页报告 · 2026-09-08 · 官方文档 + 学术论文 + 本地源码三重交叉验证

0 · 先回答问题：Hermes Agent 的"外置向量库"是怎么回事？

纠偏：Hermes Agent 的内置记忆并不用向量库——L1 是两个 Markdown 文件（MEMORY.md ≤2200 / USER.md ≤1375 字符，tools/memory_tool.py:924）；L2 会话搜索是 SQLite FTS5 全文索引（unicode61 + CJK trigram，hermes_state_common.py:661），BM25 取 top-3 会话再由辅助 LLM 摘要做"软重排"，官方概括为 "SQLite FTS5 + LLM 摘要 + 文件级持久化" [1][2][3]。 向量库确实存在，但是"外挂"的：通过 plugins/memory/ 下 8 个记忆提供者插件接入（mem0、supermemory、retaindb、hindsight、honcho、openviking、byterover、holographic），由 MemoryManager 强制同一时间只激活一个外部提供者，与内置记忆并行工作，内置写入会镜像同步给提供者 [1][2]。

1 · Hermes Agent 记忆栈（L0–L2）：触发时机与召回方式

层存储形态何时触发（写入/注入）何时召回、怎么召回
L0 工作上下文系统提示词内的冻结快照会话开始时一次性装配（L1 快照 + 提供者块）；会话中不回改以保住前缀 KV 缓存全程常驻上下文，无需检索
L1 持久记忆MEMORY.md/USER.md（原子写 + 注入扫描）Agent 经 memory_tool 自主编辑（添加/替换/移除），立即落盘下次会话开始整体注入 L0，不检索、全量注入
L1.5 外部提供者各提供者后端（向量库/图/云）见下方共享时序 [1][2]每轮前后台 prefetch 预取注入；Agent 也可主动调提供者搜索工具

② 每轮之前

2 · 主流外置记忆系统：触发时机与召回算法对照

系统存储形态写入何时触发召回何时触发召回算法
MemGPT / Letta [4][5]main context（窗口内）+ external context：recall 存储（历史）+ archival 存储（向量库）Agent 自主：LLM 函数调用自写记忆；上下文 FIFO 溢出时系统自动递归摘要旧消息压入 recall 存储Agentic 按需：LLM 自己决定调用 archival_memory_search / conversation_searcharchival 为语义向量检索（按需查询、不能常驻）；core memory 常驻且可自编辑
Mem0 [6]向量库（dense embeddings，可选图变体 Mem0g）每轮自动两阶段：抽取（结合最近 m=10 条消息抽候选事实）→ 更新（向量检索 top-s=10 相似旧记忆，LLM tool-call 判定 ADD / UPDATE / DELETE / NOOP）每次查询自动问题嵌入 → 向量库相似度 top-k（可选 LLM 重排）→ 注入提示词
Zep / Graphiti [7]Neo4j 时序知识图谱（双时间轴：事件时间 vs 摄取时间，矛盾边自动失效）每条消息作为一个 Episode 摄取：结合最近 n=4 条消息抽取实体/事实边，带参考时间戳每次查询自动混合检索：余弦语义 + BM25 全文（Lucene）+ BFS 图遍历（可用最近 Episode 作种子）→ RRF / MMR / 交叉编码器重排 → top 边+节点（实验取 20 条边）
Generative Agents（经典基线） [8]记忆流（事件流 + 嵌入向量）每个观察/行动即时写入记忆流每个决策点（规划、是否反应、生成对话、反思）三因子打分取 top-k：score = α·recency + α·importance + α·relevance（α 全为 1；recency=指数衰减 0.995/小时；importance=LLM 1–10 评分；relevance=嵌入余弦；min-max 归一）

范式 A · Agentic 自主触发（MemGPT/Letta）

把记忆管理当工具调用交给模型：检索本身消耗一个决策，模型自主判断"上下文不够 → 搜记忆"。优点是精准省 token，缺点是依赖模型自觉，可能漏召回。LLM 像操作系统一样在主存/外存间分页（virtual context management），用中断机制交还控制流 [4]。

范式 B · 自动管线触发（Mem0 / Zep / Hermes 提供者）

记忆写入与召回对模型透明：每轮消息自动抽取+去重落库，每次查询自动向量/混合检索后注入提示词。延迟可控、不依赖模型自觉；代价是每轮固定多一次检索 + 抽取开销（Mem0 论文主打低延迟：92% 低于全上下文）[6]。

范式 C · 决策点打分触发（Generative Agents）

每个行动决策点全量检索，用 recency × importance × relevance 加权排序——"什么时候触发"退化为"每个决策都触发"，重心全在排序函数上。该三因子框架至今是记忆召回排序的默认起点 [8]。

结论："最主流"不是一个系统而是一个谱系——越靠 LLM 自觉（Agentic）召回越省但可能漏；越靠自动管线（托管式）召回越稳但有固定开销。工业界当前主流收敛在范式 B（Mem0/Zep 式"每轮自动写 + 每查询自动混合检索"，Hermes 外部提供者也走这条时序）；排序底座默认仍是 Generative Agents 三因子 [1][6][7][8]。Hermes 内置栈是成本优先的反例：FTS5 关键词召回 + LLM 摘要重排替代向量检索，语义泛化推迟到摘要阶段 [2][3]。
