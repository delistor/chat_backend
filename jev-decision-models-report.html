核 心 结 论
2026 年 9 月出现的「决策模型」（Decision Model）把 AI 的「判断」从「生成文本」里拆了出来： 输入一段状态 + 若干带类型的问题，一次前向传播直接输出带置信度的结构化决策（选哪个 / 打几分 / 是不是）， 全程不写一个字。官方口径比 LLM 快约 194 倍、便宜约 445 倍；第三方与我方实测均证实「毫秒级延迟、万分之一元级成本」成立。 它不是替代 LLM，而是给 Agent 装上廉价的「条件反射层」——判断类调用用它，生成与推理仍归 LLM。

vs LLM
LLM 是「生成式慢思考」：逐 token 写答案，秒级延迟、分/厘级成本、输出要解析、可能幻觉、置信度不可靠。决策模型是「判别式快反应」：一次算完、输出即接口、零文本幻觉、概率经专门校准。两者是分工，不是替代。
vs BERT
同一族编码器骨架（开源版 Laya 的骨干就是现代版 BERT），但 BERT 分类器的标签焊死在训练里，换个任务就要重新标注重训；决策模型的标签写在每次请求里，还能一次批量回答多个问题，并用强化学习专门训练「概率说真话」（校准）。

1决策模型是什么：只做判断、不写文章的 AI

2026 年 9 月 15 日，TypeSafe AI 发布 Jev，自称业界第一个「System One 模型」。这个名字取自心理学家卡尼曼《思考，快与慢》中的双系统理论：

System 2 —— 大语言模型（LLM）

慢思考：逐字斟酌、可以推理、能写长文。每次调用都在「写一段话」，哪怕你只要一个 yes/no。慢、贵、输出需要再解析，偶尔一本正经地胡说（幻觉）。

System 1 —— 决策模型（Jev 等）

快反应：像刷卡时的银行风控——瞬间给出「放行 / 拦截 / 升级人工」和把握有多大。不解释、不啰嗦，输出直接就是程序能执行的类型值 + 校准过的概率。

◆一次调用长什么样（以客服工单分流为例，开源版 Laya 真实接口）

// 输入：一段状态（state）+ 三个带类型的问题，一次提交 state = "We were billed twice for March. Refund today or we cancel." questions = { department: { type: choice, criteria: { billing: "invoices…", technical: "bugs…", sales: "pricing…", other: "…" } }, urgency: { type: score, criteria: ["not urgent", "soon", "critical"] }, churn_risk: { type: noul, instructions: "Does the user threaten to cancel?" } // 输出：一次前向传播，三个答案 + 概率，没有任何生成文本 { department: "billing" (p=0.94), // 路由到哪个组 urgency: 1.84 / 2.0, // 紧急度打分 churn_risk: 0.892 } // 「会流失吗」的校准概率

三种「决策原语」覆盖了业务里绝大多数判断类需求：

原语回答什么输出典型用途
choice在 N 个选项里选一个（Jev 最多 255 个）选中项 + 完整概率分布意图分类、路由、打标签、工具选择
score在有序等级上打分期望分 + 分布紧急度、严重程度、情绪强度
noul是 / 不是校准概率 P(true)，0–1钓鱼检测、越狱识别、流失风险、质检

◆三周之内，品类已经立住

判断一个方向是真趋势还是营销，最简单的办法是看有没有大厂跟进、有没有开源复现、有没有论文。Jev 三周内三者全齐：

为什么现在出现？——需求倒逼。 Agent 每完成一个动作，内部要做几十次「小判断」（走哪条分支、用哪个工具、要不要升级）。全用 LLM 做这些判断， 成本和延迟直接爆炸——Cloudflare 内部实测：同样一批域名分类任务，用 27B 开源 LLM 跑要 4.7 秒，换成决策模型 2.2 秒跑完。〔三〕 「便宜的判断层」是 Agent 规模化的前提，这个空档在 Jev 出现之前没有专门的产品填。

2与大语言模型（LLM）的区别：从架构到经济账

◆五个本质区别（三方对照）

维度LLM（生成式）BERT 分类器（判别式老前辈）决策模型（判别式新品类）
计算方式自回归解码：生成 N 个 token 循环 N 次前向，延迟随输出长度浮动一次前向（这点和决策模型一样快）非自回归：无论几个问题几个选项，固定 1 次前向，延迟近乎常数
输出形态自由文本 → 需要解析，解析失败 = 程序崩溃点；JSON 模式只约束格式、不减少计算1 个 argmax 类别，无分布、无多问题结构化类型值 + 完整概率分布，程序可直接 if/else
幻觉生成任务固有风险，判断任务里表现为「编造答案或错误理由」不生成文本，无幻觉（但选错也不解释）不生成文本，结构上不存在文本幻觉（仍可能选错，见 §8）
置信度口语说「95% 确定」不可信；token 概率未经校准且过度自信softmax 概率可用，但从没为「报准把握」训练过用「真值评分规则」当奖励专门训练（RLCD），校准后 ECE 0.47→0.08〔官〕，概率可当工程阈值
经济性判断类调用 $0.002–0.02/次、秒级；官方样例：同任务 $0.01388 / 8.6s〔官〕毫秒级、自托管近零（但要为每个任务养一个模型）同任务 $0.000081 / 0.11s〔官〕；第三方实测 3,080 次分类共 $0.34〔三〕
改任务/标签改提示词即可（灵活但每次都贵）重新标注 + 重训 + 发版（最贵）改请求里的一个字符串即可（灵活且便宜，这是新品类的立身之本）
▸ 技术注解 1：LLM 能否承担判断任务？——能，但代价不成比例

arXiv 2610.02076《LLM-as-Jev》证明：现代 LLM 不经任何改造就能当决策模型用——让每个选项带一个编号（如 [3]）， 直接读「下一个 token 是编号几」的概率分布，就得到各选项概率。实验中 Qwen3.5-4B 零训练即追平同底座的社区决策模型，还天然支持图片等多模态判断。

但注意代价：每判断一次仍要跑一遍 LLM 的完整前向（几十亿~千亿参数），延迟与成本只比让它「写答案」略省，比 4 亿参数的专用决策模型贵 1–2 个数量级。 论文的结论恰好反证了新品类的价值：判断这件事值得用便宜 100 倍的专用机器来做；微调（LoRA + KL 锚定）只在弱底座和多选项路由等场景有增量收益。

另外，「JSON 模式 / 结构化输出」解决的是格式问题——保证输出能解析；它不减少计算量、不解决校准、不改变逐 token 生成本质，所以与决策模型不是一回事。

3与 BERT 的区别：同一个骨架，完全不同的用法

这是最容易混淆、也最能体现「新品类」含义的对比。决策模型并没有发明新的网络结构——开源版 Laya 的骨干就是 ModernBERT（BERT 的 2024 年现代化版本，395M 参数）。新的是三件事：

维度BERT 分类器（2018 →）决策模型（2026 →）
标签在哪定义训练时焊死在分类头权重里。新增/修改一个标签 = 重新标注数据 + 重新训练 + 重新发版写在每次请求里。标签是对一段文字描述打分，改标签 = 改一个字符串，即刻生效，无需重训
输出什么1 个 argmax 类别（要概率也有，但没做过校准训练）多问题并行作答：完整概率分布 + 有序分 + 布尔概率，且概率经过校准训练
训练目标交叉熵：只优化「选对」，不管「有多确定」RLCD（校准决策强化学习）：奖励函数是严格真值评分规则——概率报得诚实才有奖励，过度自信会被罚

◆机制图：标签为什么能「写在请求里」

一句话理解三者的「血缘」。 BERT 贡献了「读句子」的身子，LLM 贡献了「按自然语言指令办事」的灵魂，决策模型把两者拼起来并加上「概率说真话」的风控级训练—— 新在用法与训练目标，而不在「更大」：Laya 全部 421M 参数，是主流 LLM 的百分之一。
▸ 技术注解 2：RLCD —— 「校准」是怎么被训练出来的

普通分类训练（交叉熵）只关心选对；RLCD（Reinforcement Learning for Calibrated Decisions，Laya 与 Cloudflare Clef 均采用）把「概率报得准不准」本身做成奖励：

· 奖励 = 对数评分规则 + 球面评分规则（有序分级另加排序概率分）——这类「严格真值评分规则」的数学性质是：只有诚实报出真实把握，期望奖励才最大，盲目自信必被罚；
· 用 GRPO 式组内基线的 REINFORCE 优化，多轮决策加 TD(λ)；Clef 还额外加了 Brier 损失与「防止分布漂移」的参考惩罚。

工程含义：即便如此，开源版出厂仍是过度自信的（官方自测：拟合温度前 ECE 0.466 → 拟合后 0.081〔官〕），上线前必须用自己领域的数据重新拟合温度——此为我方实测确认的首要工程事项（§5）。

▸ 技术注解 3：两条技术路线 —— 编码器原生 vs 大模型改造

路线 A · 编码器原生（Laya）：ModernBERT / mmBERT 骨干 + 从头训练的决策头（2 层 Transformer + 选项打分器）。小（322–421M）、快（毫秒级）、单卡可跑，代价是语言覆盖与复杂推理弱。

路线 B · 大模型改造（Cloudflare Clef、社区 Kev、LLM-as-Jev）：冻结一个现成 LLM（Qwen3.8-27B / Qwen3.5-9B 等）当「世界知识底座」，只训轻量决策头 + LoRA 适配器（秩 256）。基准分数更高（如 Banking77 macro-F1 94.2 vs Laya 的 42.5〔三·Cloudflare 统一评测〕）、带视觉、上下文 64k，代价是延迟数十至数百毫秒、部署门槛高。

两条路线印证同一个判断：「判断层」的价值在成本-质量曲线上，不在单点最优——够准 + 便宜 100 倍，就能改变系统架构。

我们用贪吃蛇做了一个完整的微调实验（每步一次前向回答「走哪边 + 四个方向会不会撞死」），验证从基础模型到可用品的全部工序：基础模型域外接近随机水平 → 行为克隆（SFT）消除顽固偏好 → 回合级强化（GRPO）进一步提升，全程冻结 394M 编码器、只训 26.5M 决策头，一张消费级显卡约 3 小时。完整数据与三种模型同题对照见 §6。

▸ 工程坑备忘（来自我方实测，供团队落地参考）

① 出厂概率不可直接当阈值：必须按（问题类型 × 选项数）重新拟合温度，ECE 才能从 0.47 降到 0.08 量级；实测中还出现过置信度 1.00 的错误答案——高置信 ≠ 正确。
② 输入格式影响高达 13 个百分点：同样内容，裸字符串 vs 按预设规范的 dict，准确率差 13pp，且模型不会报错、只会悄悄变差。
③ 选项 >50 个会退化（每个选项分到的 token 预算不足），需调大预算或改两级选择；Jev（LLM 底座）在此场景更强。
④ 它不解释：每个问题独立打分，不生成理由，需要解释时另接生成模型。
⑤ 并发不是杠杆、批处理才是：16 线程只快 13%（Python 分词占大头），按 25 题/批调度才能吃满吞吐；跨请求微批可再省 87% 的前向次数。

6实例：让决策模型实时玩贪吃蛇——同一任务，三种模型会怎么做

公开基准数据难以完全回答业务适用性问题，为此我们进行了一项可现场演示的端到端实验：由 Laya 实时驾驶贪吃蛇。该任务规模虽小（15×15 棋盘），但蛇每走一步都是一次标准的 Agent 决策：读取状态 → 做出判断 → 执行动作，且必须满足实时约束（200ms 一步）。我们向模型输入结构化坐标状态（棋盘尺寸、蛇头/食物坐标、四邻格内容），每步提出 5 个问题——「走哪边」（choice）+ 四个方向「会不会立即撞死」（noul）——一次前向传播全部答完（61ms），概率直接驱动蛇的移动。选项文字由引擎每步现场生成，将确定性后果写入选项描述：step left: head to (6,7), onto your own body。

◆三点实测发现（均有数据支撑）

发现一：输入的表达方式对效果影响显著，且 BERT 类模型读文本、不读图。我们迭代了三轮输入格式（同一批 120 个棋盘带真值对比）：

输入格式合法率不撞墙率撞死判断准确率撞死判断 AUC单步延迟
① 纯 JSON 坐标0.600.580.3710.416~50ms
② JSON + ASCII 地图（「画」给它看）0.970.910.2630.46383ms
③ 坐标 + 后果式选项（现用：引擎把每个方向的落点/内容写进选项）0.950.940.7290.99161ms

ASCII 地图信息密度极低（225 个格子里绝大多数 token 是点），token 翻倍、延迟涨 25% 还更差；换成「把后果写进选项」后，撞死判断 AUC 从噪声级 0.463 飙到 0.991——不是模型变强了，是问题终于变成「可从文字推出」的了。

发现二：基础模型存在无法通过提示词消除的「内在偏好」——这是本实验最重要的发现。上线后果式输入后蛇仍然持续打转：500 步吃 0 个食物，94% 的步数在上下弹跳。三轮排查（含词汇匹配假说的阴性实验）确认：基础 checkpoint 对「上」方向存在约 +0.2 的内在偏好，强度足以压过选项中写明的后果——食物位于下方时仍选择「上」。调整输入措辞无法改变模型的先验。

发现三：正确的解法是「分工」，而非「继续校正模型」。实测确认模型真正擅长的是「排除死路 + 在好选项里挑一个」（AUC 0.99），不擅长「从四个方向里做几何导航」。于是改为引擎提名、模型挑选：引擎用 BFS 找出所有「安全且不远离食物」的走法组成候选名单，模型只能在名单内挑选。结果：500 步食物 0 → 45，方向分布 132/129/121/118 接近完全均匀，打转现象结构性消失。

这一步的架构含义，比分数更重要。 「引擎提名、模型挑选」正是 Agent 的标准协作范式——工具负责确定性计算（坐标、碰撞、检索），决策模型负责在描述清楚的选项里做判断， 每步 61ms、零边际成本。Jev 生态里的浏览器 Agent、手机 Agent（§4 应用表）用的正是这个模式。

7对我们的意义：Agent 架构里的「快层」

我们做 Agent 应用，这正是决策模型的主战场。核心模式一句话：用决策模型「包夹」LLM——入口、分支、出口的判断全部下沉到毫秒级快层，LLM 只在真正需要推理与生成的环节出场。

8风险与边界：四项关键风险及应对

① 鲁棒性是当前最大的技术风险：决策输出可被精心构造的上下文翻转。 arXiv 2609.30243《JevOut》实测：在输入中加入语义完全正常的上下文（不改问题、不改选项、不改正确答案）， 能将 Jev 61.4% 的原本正确的判断翻转为高置信错误（≥0.7 置信）；四款受测决策模型的被翻转率为 64.9%–73.2%〔三〕。 这意味着用于防御提示注入的模型，自身同样面临注入风险。对策：护栏与业务判断不共用同一套问题模板；高价值动作前增加规则白名单或二次校验；将对抗样本纳入上线门禁。
② 「开箱即用」并不成立，「微调后方可用」才是现实。 所有开源基础版在专用业务域上的表现接近随机（官方自测 36 分，低于 46 分的多数类基线〔官〕；我方级联实验中，未微调模型的自动处理上限仅 47%〔我〕）。 真实成本 = 模型（免费）+ 标注数据 + 微调工序 + 校准工序 + 格式规范管理。上述工序我方已全部跑通且单卡可完成；但每个场景均需完整执行一遍，无法复用捷径。
③ 校准需要专门训练，且出厂状态普遍过度自信。 官方自测：不重新拟合温度时，置信度误差 ECE 高达 0.47（0 为完全校准）；拟合后降至 0.08〔官〕。我方实测中亦出现过置信度 1.00 的错误答案。 工程纪律：置信度必须先在自有数据上完成校准，方可作为阈值使用；线上须配备「置信 ≠ 正确」的监控兜底。
④ 能力边界清晰：不提供解释，不擅长多选项与开放推理。 每个问题独立打分，不生成理由（需要解释须另配生成模型）；选项超过约 50 个时小模型明显退化（Banking77 上 42 分 vs Jev 87 分〔官〕）；「打分」原语为公认弱项（SST-5 仅 0.37〔官〕）。 此外品类发布仅三周，API 标准与生态仍在快速变动——但 Jev 的接口契约已成为事实标准，主流开源实现全部兼容，切换成本可控。

9结论：三个判断，三条建议

三个核心判断

① 品类成立，方向被确认。三周内官方产品、Cloudflare 开源、社区复现、arXiv 论文全部到位；「判断层」是 Agent 规模化的真实空档。
② 不替代 LLM，而是重新分工。判断下沉到毫秒/万分之一元的快层，LLM 专注推理与生成——综合成本可降一半上下，响应更快、行为更可预测。
③ 长期壁垒在使用数据，不在模型。模型免费开源、微调单卡几小时；自有判断数据与微调闭环才是难以复制的核心竞争力（贪吃蛇实验已完成全流程验证，§6）。

三条建议

① 试点先行：以「入口护栏 + 意图路由」场景切入，30 天内产出灰度验证数据，不做全量替换。
② 开源起步、数据自持：沿用我方已部署的 Laya 路线（Apache 2.0），把每个场景的真值数据当资产经营；接口兼容让未来切换 Clef 或采购 Jev API 都不改代码。
③ 把「校准 + 鲁棒性」纳入上线门禁：温度重新拟合、对抗上下文测试、置信监控三项缺一不可——这是决定其能否成为生产级组件的分界线。
