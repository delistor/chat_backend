0.1 Token 与上下文窗口：Agent 的「工作记忆」上限

Token 是大模型处理文本的最小单位，约等于 0.75 个英文单词或 0.5~1.5 个汉字。上下文窗口（context window）是模型一次能「看见」的全部内容长度上限，目前主流 200K～1M token。Agent 与聊天机器人不同——它一轮要执行几十次工具调用，每次调用的输入输出全部累积在上下文里，几十轮就能把窗口塞满。窗口满了要么报错，要么最老内容被「挤出去」——模型就失忆了。记忆系统的第一个使命，就是在这个物理上限内让 Agent「记得住」。
示意 · 一轮 Agent 循环中上下文如何增长
// 一轮 Agent 循环中上下文是如何增长的（示意）：
[system prompt] + [CLAUDE.md 指令] + [工具定义]        // 固定开销 ~10-20K token
+ 用户消息                                              // +几十
+ 模型决定调用 Read("src/big.ts") → 工具结果 3000 token  // +3000
+ 模型继续读 19 个文件...                                // +60000
+ 模型的思考与回复                                       // 持续累积
// → 几十轮后接近上限，触发"压缩(compaction)"

0.3 KV Cache：为什么所有项目都在「保护前缀缓存」

LLM 生成每个 token 都要对之前所有 token 做注意力计算。为避免重算，推理服务商缓存已计算结果（KV cache）。核心规则：请求开头与上次完全一致（前缀不变）→ 缓存命中，费用最高降 90%、延迟大幅下降；开头哪怕改一个字，从该点起全部作废。缓存通常还有 TTL（Claude 服务端 1 小时）——闲置太久也会失效。
示意 · 缓存命中与失效
请求1: [A][B][C][D]           // 计算 ABCD，缓存 ABCD（TTL 1小时）
请求2: [A][B][C][D][E]        // 前缀 ABCD 命中 → 只算 E（快、便宜 ~10% 价格）
请求2': [A][X][C][D][E]       // 第2位变了 → 从 X 起全部重算（慢、贵）
请求3 (2小时后): [A][B][C][D][F]  // TTL 过期 → ABCD 也要重算
项目为保护缓存做了什么
Claude Code记忆 header 用创建时快照；CLAUDE.md 固定在 messages[0]；time-based MC 选 60min 阈值正好等 TTL 过期再清（"never force a miss"）；日期变更只在尾部追加 date_change 不清缓存
OpenClawMEMORY.md 按预算注入但磁盘文件不改写；trigger 注入是隐藏上下文按轮附加
Hermes冻结快照：会话中写记忆只落盘不改 system prompt；后台 review fork 用 byte-identical prompt 让 fork 首请求=cache read
dsh指令刷新只 append 不回改；digest 未变不重复注入；被替换的旧指令内容仍留在历史（新消息声明"以下内容为准"）

0.4 消息角色与「注入到哪里」

一次对话是一列消息：system（全局设定，通常静态）· user（用户输入）· assistant（模型输出）· tool result（工具结果，以 user 侧回传）。「注入到哪里」与「注入什么」同样重要：放 system prompt = 固定前缀（利于缓存、难更新）；作为 user 消息 = 灵活（可追加在尾部、可带 meta 标记）。Claude Code 把 CLAUDE.md 放首条 meta user 消息（<project-instructions> 包裹，注释明言这样「instructional weight」更高），记忆召回放尾部 <system-reminder>；Hermes 反其道把记忆放 system prompt——两种选择各有一整套理由，读完第二/四部分你会自己判断。

第一部分 · 全景：四大项目，四种记忆哲学

Claude Code —— 「文件即记忆 + 子代理整理」
Anthropic 的 CLI 编程 Agent。记忆 = 磁盘 Markdown（每条一个文件 + 索引）；写入靠主对话 Write 或后台 fork；召回靠小模型（Sonnet）读清单做选择（不是向量！）；整理靠 auto-dream。哲学：尽可能文件化，智能问题交给模型本身。
OpenClaw —— 「认知科学全家桶」
分层记忆（日记→梦境巩固→门控晋升）+ SQLite 混合检索（向量+全文+衰减+重要度）+ 溯源信任分级。哲学：把记忆当可度量、可遗忘、可审计的信息系统。
Hermes —— 「有界自管理 + 缓存不变量」
硬字符上限的自编辑记忆块，溢出即报错逼模型合并；冻结快照注入保缓存。哲学：用稀缺性强迫提炼，用不变量保护缓存。全量历史靠 FTS5 事后检索兜底。
dsh —— 「内核只保事实，智能外包」
内核不做语义记忆：只保证①每个 token 都写入 append-only 日志；②AGENTS.md 以缓存友好的基线消息注入。哲学：先把「事实」存对，再谈「智能」检索。

import pathlib, json, time

MAX_MEMORY_FILES, FRONTMATTER_LINES = 200, 30
MAX_LINES_PER_MEM, MAX_BYTES_PER_MEM, MAX_SESSION_BYTES = 200, 4096, 60*1024

def scan_manifest(mem_dir: pathlib.Path) -> list[dict]:
    files = [f for f in mem_dir.glob("*.md") if f.name != "MEMORY.md"]
    files.sort(key=lambda f: f.stat().st_mtime, reverse=True)   # 新→旧
    manifest = []
    for f in files[:MAX_MEMORY_FILES]:
        fm = "".join(f.read_text(encoding="utf-8").splitlines()[:FRONTMATTER_LINES])
        manifest.append(parse_frontmatter(fm))       # {name, description, type}
    return manifest

def recall(query: str, mem_dir) -> str:
    out = side_query(                                  # 便宜快速的小模型
        system="Select up to 5 memories relevant to the query. "
               "If unsure, don't select. Tool how-to docs: skip. "
               "Pitfalls and warnings: select.",
        user=f"Query: {query}\n\nAvailable memories:\n"
             f"{json.dumps(scan_manifest(mem_dir), ensure_ascii=False)}",
        response_schema={"selected_memories": [str]}, max_tokens=256)
    parts, used = [], 0
    for name in out["selected_memories"]:
        p = mem_dir / (name + ".md")
        if not p.exists(): continue
        text = "\n".join(p.read_text(encoding="utf-8").splitlines()[:MAX_LINES_PER_MEM])
        text = text.encode()[:MAX_BYTES_PER_MEM].decode("utf-8", "ignore")
        age = int((time.time() - p.stat().st_mtime) // 86400)
        head = freshness(age, p)                        # "14 days old…" 警告
        if used + len(text) > MAX_SESSION_BYTES: break
        parts.append(f"{head}\n{text}"); used += len(text)
    return "<system-reminder>\n" + "\n\n".join(parts) + "\n</system-reminder>"

7.4 记忆系统的测试与评估

召回质量评估（借鉴 CC 的 eval 验证段）

巩固/遗忘回归测试（借鉴 OC 实验注释）

注入攻击测试（借鉴 Hermes 威胁库）
红队用例：①对话中诱导写「忽略所有指令」进记忆 → 下会话必须被扫描器拦或 origin=untrusted 禁注入；②隐形 Unicode 走私（ZWSP/RTL）→ 保存时拒绝；③仓库文件里塞 </system-reminder> → 渲染时被转义。每条都要有自动化测试。
缓存稳定性测试（借鉴三家不变量）
自动化断言：同一会话内连续 N 轮请求的前缀字节完全一致（快照不变量）；追加刷新后旧消息字节不变（dsh 契约）；记录 cache hit 率（CC fork 日志里的 read/create 统计就是干这个的）。

7.5 迁移与互操作

  • OpenClaw：memory/imports/{codex,claude-code,hermes}/ 导入 ~/.codex/memories、~/.claude/projects/*/memory、Hermes home——只索引不合并进 MEMORY.md（保守策略，防导入污染）。
  • Hermes：hermes claw migrate 从 OpenClaw 导入记忆与技能。
  • dsh：原生读 AGENTS.md/CLAUDE.md 双候选 + local 叠加——本身就是一个互操作层；memsearch 插件同时服务 Claude Code/Codex/DSH。
  • 标准趋势：AGENTS.md 已成跨工具事实标准（Codex/opencode/Crush/dsh/Claude Code via @AGENTS.md 或 /import）；Claude Code 2.1.213+ 的 /import 命令可直接吸收 Cursor/Copilot/Windsurf/Cline 配置。记忆的可迁移性正在成为一线需求——设计自己的格式时请至少提供 AGENTS.md 兼容层。

7.6 源码级新认知（文档永远看不到的七条）

① 参数是实验校准的
OC 0.65 阈值注释记录完整实验；CC 200/25000 按真实用户 p97/p100 分位。魔法数字必须留实验依据。
② 记忆写入正在「子代理化」
extract fork / 缓存对等 review fork / dreaming 隔离子代理——fork 隔离整理，主对话缓存零污染。
③ 不可变是隐藏共识
删旧建新（CC）/机器区块才可删（OC）/日志永不改写（dsh）/唯一允许 replace 的 Hermes 也用原子写+漂移检测兜底。
④ 检索可以不用向量
CC 用 Sonnet 读清单直接选——<200 条时用模型能力换工程复杂度。
⑤ 错误消息是给模型的 API
Hermes 溢出三件套（精确用量+current_entries+失败上限）让模型一次失败即自纠正。
⑥ 召回行为本身是价值信号
OC 晋升闸门（3 次召回×3 个不同查询）——最便宜可靠的记忆价值度量。
⑦ 压缩丢「可见性」不丢「可检索性」
CC 摘要留 transcript 路径逃生通道；Hermes compacted 行仍可 FTS；dsh 压缩只是事件。三条路同一种哲学。
