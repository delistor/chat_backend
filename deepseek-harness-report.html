§TL;DR · 一页看懂（给没时间的朋友）

DeepSeek 官方给它的一句话是：Agent = 模型 + Harness。

  • 模型是一匹力气很大的马——会想、会说、会写，但光有脑子，不会自己动手干活。
  • Harness 这个词本义就是「马具 / 缰绳」——给马套上缰绳，它才能拉车、耕地，把力气用在正事上。

所以 DeepSeek Harness 干的事是：给 AI 装上「手脚」和「工具」，让它不只是动嘴出主意，而是真的去读文件、跑命令、查资料、记事情、把任务做完。

它最特别的一点，藏在它的口号里——「一切皆插件」（Everything is a Plugin）。用我们自己的比喻说：它是一块万能插座，本身几乎不干正事，只负责让各种「电器」插上去、通上电、互相配合，而且随时能把某台电器拔下来换一台，整个系统不会坏。

🔌

一切皆插件

记忆、界面 Logo、模型、沙箱……连 AI 的「大脑运转方式」本身都是可换的零件，没有焊死的部分。

⚡

接进去 = 通上电

零件靠三个接口接入：供电、通电（在正确时机自动插一脚）、占灯座（换外观）。

🔧

适合二次开发

一切可自定义、可热插拔、可回滚；先做「会做什么 + 记住什么」两块最小零件，边做边拼。

过去造一个 AI 助手是买一台封死的整机；现在是从一盒标准零件的工具箱里，拼自己那台，而且任何一块都能随时换。

2「一切皆插件」：为什么这不是一句空话

很多软件都说「支持插件」，但绝大多数是 「一台整机 + 几个外挂口」：机器本身焊死了，你只能往预留的接口上拧小配件。DeepSeek Harness 的差别是——它根本没有那台焊死的机器。

底座（Cordis）极薄，只做三件事

整个系统唯一的「固定部分」，是一块叫 Cordis 的底座。它没有任何业务逻辑，只负责：① 插上零件、② 拔下零件、③ 记住「谁依赖谁」。剩下的一切——记忆、界面、模型、沙箱、连 AI 的主循环——都是插在它上面的零件。

拔得干净（可逆）

每个零件进来做的每一次改动，都提前登记好「怎么还原」。拔掉它时，系统倒着把改动撤销，恢复原样——不漏、不残留、不崩。

拿 smolagents 的源码，看「传统 agent」到底怎么做的

为了看清「核心焊死」到底长什么样，我们把 HuggingFace 的 smolagents（目前最主流的轻量 Python agent 框架）源码拉下来看。它的循环，全部写在一个大类里：

# smolagents/src/smolagents/agents.py —— 循环、记忆、调模型、跑工具，全在一个类
class MultiStepAgent(ABC):              # 整个 agent 就是一个类
    def run(self, task, ...):               # 入口：初始化 → 调 _run_stream
    def _run_stream(self, ...):             # ReAct 主循环：就写死在这里
        self.step_number = 1
        while not returned_final_answer and self.step_number <= max_steps:
            ...
            for output in self._step_stream(action_step):  # 每一步：调模型→解析→跑工具
                ...
    def _step_stream(self, memory_step):      # 抽象方法：子类必须自己实现这一步
        raise NotImplementedError("This method should be implemented in child classes")

而「一步」里干的事，也在同一个类里排得明明白白（子类 ToolCallingAgent._step_stream）：

# 一步 = 读记忆 → 调模型 → 解析工具调用 → 逐个执行 → 记结果
memory_messages = self.write_memory_to_messages()       # ① 把历史写成发给模型的消息
chat_message = self.model.generate(memory_messages, ...) # ② 调模型
self.model.parse_tool_calls(chat_message)              # ③ 解析出工具调用
for output in self.process_tool_calls(chat_message, ...): # ④ 逐个执行工具、记结果
    ...
yield ActionOutput(output=final_answer, ...)          # ⑤ 吐出结果，回到 while 再跑

想给它加能力（比如「记忆」），smolagents 只给两条路：

办法代价
继承改源码——子类重写 write_memory_to_messages / _step_stream要动「核心方法」本身，你的改动和原逻辑缠在一起
事后回调——注册 step_callbacks / final_answer_checks只能在每步跑完之后看一眼，没法在「动脑前」往输入里塞东西
同一个「记忆」需求，两种改法

在 smolagents 里，想让 AI 动脑前先看到相关记忆，只能继承 MultiStepAgent、重写 write_memory_to_messages()——等于拆开机器改线路；在 DeepSeek Harness 里，这是插一个 ctx.on("agent/pre-step", …) 的零件——循环一行都没碰。前者「改源码」，后者「插零件」。

这也正好呼应了上面表格里「核心能换吗」那一列：smolagents 的核心循环就写在类里、要改得改源码；Harness 的核心循环自己就是一个插件，能被整体替换。

一句话：传统框架是「给你一台机器，你拧配件」；Harness 是「给你一盒零件，你自己拼机器」。代价是上手门槛更高，换来的是一切都能换、能改、能回退。

3先看一个例子：它怎么「记得」张伟是湖北人

空谈概念容易晕。我们用一个真实能跑的例子——我们自制的 记忆零件（名字叫 dsh-memory）——演示「一切皆插件」到底意味着什么。

第一场对话：把一件事记下来

你记住：张伟是湖北人。
AI好的，已经记下了：张伟是湖北人。

这时，记忆零件看到「记住：」两个字，就把「张伟是湖北人」存进了本地一个「记忆本子」（就是一个文件）。

第二场对话：换一个全新的话题，再问一次

注意，这是另一场全新对话——正常情况下 AI 已经「失忆」了，它不记得上一场说过什么。

你张伟是哪里人？
AI张伟是湖北人。

它答对了。为什么？因为在你提问、AI 动脑之前，记忆零件悄悄做了一件事：它拿你新问的话（「张伟是哪里人？」）去「记忆本子」里翻，翻到了相关的「张伟是湖北人」，就把它抄在问题的旁边，再一起交给 AI。于是 AI「想起来了」。

更精确地说，AI 每一次「动脑」，收到的是一份「消息清单」（messages）。记忆零件做的事，就是在这份清单末尾多加一条：

📥 主循环默认的清单

[0] 你问的话：张伟是哪里人？
[1] 运行时上下文（系统塞的现场信息）

⚡ 记忆零件 next() 之后

[0] 你问的话：张伟是哪里人？
[1] 运行时上下文
[2] 记忆小抄：张伟是湖北人  ← 新增

主循环随后会把清单里的每一条都写进 AI 的输入，于是 AI 看到第 [2] 条，答出了「湖北人」。

三步看懂这个「记忆」

① 你说「记住…」→ 零件把话存进本地文件；② 新对话里你一问 → 零件在 AI 动脑前，翻出相关的那句，塞进幕后；③ AI 看到小抄 → 答对。整个过程，我们没有改 AI 本身，只是插上了一个「记忆」零件。

这就是「一切皆插件」的第一层意思：「AI 有没有记忆」不是一个写死的能力，而是你有没有插上「记忆」这个零件。插上，它就记得；拔掉，它就变回金鱼。

4三个插座：一个零件怎么「接进去」

知道了「零件」这回事，下一个问题是：零件靠什么和系统配合？答案记成三种插座：供电、通电、灯座。

① 供电我提供一个能力，别人能用。比如「记忆」零件对外提供一本「记忆本子」。
② 通电（事件）在 AI 干活的固定时机，自动插一脚。这是「介入事件流」。
③ 灯座（插槽）界面留的空位，谁把灯泡拧进去，谁就亮。换 Logo 就靠它。

4.1 供电（服务）：提供一个「能力」，别人能用

三种插座里最基础的是「供电」：一个零件可以提供一个能力，挂到系统里，让别的零件直接拿到、直接用，不用关心它内部怎么实现。

// 记忆零件：把「记忆本子」做成一个服务，挂成 ctx.memory
class MemoryService extends Service {
  constructor(ctx) {
    super(ctx, "memory");    // 注册成 ctx.memory
  }
  remember(内容) { ... }        // 对外提供「记」
  recall(查询)  { ... }        // 对外提供「回忆」
}

挂好之后，任何别的零件、任何 AI 工具，都能 ctx.get("memory") 拿到它来用——就像谁家要电，插进同一个插座就有，不必知道电厂怎么发的。dsh-memory 自己就是这么做的（源码里 super(ctx, "memory")）。

「供电」和「通电」别混了

供电 = 我提供一件东西，别人主动来取（ctx.get，拉取）；通电 = 系统在固定时机主动推给我，我被叫醒去插一脚（ctx.on，推送）。记忆零件两样都用：供电让别人能拿它的记忆本子，通电在「动脑前」自动塞小抄。

4.2 通电（事件）：在「正确时机」自动插一脚

AI 每完成一次「思考 + 行动」，都像电流沿着一条固定回路流动。回路上有几个固定的「时机点」：动脑之前、发请求时、一轮结束收尾时……

💬 你提问
开始
🧠 塞进记忆
动脑前（记忆零件挂这里）
🤖 AI 动脑
思考
🔧 干活（工具）
执行
🧾 自动记笔记
一轮结束（记忆零件挂这里）
↻ 下一轮
收尾

① 事件是什么：系统沿路「喊话」

每到上面一个「时机点」，系统都会喊一嗓子，喊的时候手上拎着一个「现场数据袋」（叫 payload），装着那一刻的情况——比如「本轮要发给 AI 的消息清单」。

零件想参与，就提前报名：ctx.on(事件名, 处理函数)，意思是「喊到这个关卡，叫我」。几个关卡名，你会在真实代码里反复见到：

agent/pre-step动脑前：模型还没想，可以往里塞东西。
agent/request真要发请求前：可以改发给模型的内容。
agent/turn-stopping一轮收尾：模型已答完，可做点收尾记录。

② 喊话的几种方式

不是所有喊话都一样。系统有几种「喊法」，决定零件能不能改东西：

喊法白话能改东西吗
emit 广播喊一嗓子，谁爱听谁听，不等回答不能（只旁观）
serial / bail 排队按报名顺序挨个问，第一个答话的算数通常用于审批 / 决定
waterfall 接力棒像传接力棒，每人拿到半成品，改一下，再传下去能（这就是「介入」）

③ 接力棒（waterfall）：介入的核心

「动脑前」的 agent/pre-step，就是接力棒型。主循环自己在最里面放好了一份「默认结果」——意思是「进入这一步，消息清单如下」：

// 主循环在最内层放好的「默认结果」
{ kind: "enter", messages: [你问的话, 运行时上下文] }

你的零件插在接力棒中间：先 next() 拿到这份默认结果，往 messages 里多加一条，再 return 传回去：

// 记忆零件：在「动脑前」这个关卡，往消息清单末尾塞一条小抄
ctx.on("agent/pre-step", async (payload, next) => {
  const decision = await next();            // 拿到默认结果 { kind:"enter", messages:[...] }
  const 记忆消息 = 造一条消息("可能相关：张伟是湖北人");
  return { ...decision, messages: [...decision.messages, 记忆消息] };  // ← 插入点：messages 末尾
});

（一条关键规则：只旁观的零件必须调用 next() 放行；要拦下做决定的零件可以不调用 next() 直接 return，等于「短路」，后面的都不跑了。）

④ 插入到哪：消息清单 → 会话日志 → 模型

你塞进 messages 的每一条，最终去哪？看主循环接下来的动作：它会把清单里的每一条，逐条写进「会话日志」——而会话日志，就是 AI 唯一看到的「输入」。

1
你往 messages 里塞一条在接力棒里 next() 后追加。
2
主循环逐条写进会话日志每一条都变成一条 user/message。
3
模型读日志看到你塞的那条，于是「想起来了」。
// 主循环内部的真实动作（简化）：把你塞进 messages 的每条，都写进会话日志
for (const m of decision.messages) 会话日志.append("user/message", m);
这就解释了「为什么易于开发」

想让 AI 在做某件事之前多看到点什么？四步：找到关卡名 → ctx.on 报名 → next() 拿默认结果 → 往 messages 塞一条 → 返回。不用改 AI 本身，不用改主循环。这就是「介入事件流」完整、可复刻的手感。

两种事件的区别（可跳过）

「动脑前」agent/pre-step 是接力棒（能塞东西）；「一轮收尾」agent/turn-stopping 是排队喊一声（只通知、不挡路，所以记忆零件在它里面只「存下来」，不塞东西）。判断一个零件「介入得深不深」，就看它挂的是接力棒还是旁观型。

4.3 内核循环：喊话的人，自己也是一个插件

4.2 一直在说「系统沿路喊话」，那到底是谁在喊？答案是一个固定的内核循环——有意思的是，它自己也是一个插件，只是全系统只有它一个装了「具体循环逻辑」。

它是这么定义的：一个「服务式」零件

记忆零件用 apply(ctx) 注册就够了；内核循环换了一种更「重」的写法——服务式零件，因为它要对外提供一个别人会依赖的接口 ctx.agentLoop：

// 内核循环 = 一个 Service 类插件（官方包 @deepseek-ai/dsh-agent-loop）
class AgentLoop extends Service {
  static inject = ["agents", "sessions", "llm", "tools", "systemPrompt"];
  constructor(ctx) {
    super(ctx, "agentLoop");           // 把自己挂到 ctx.agentLoop
    ctx.agents.setFactory(this);         // 再注册成「造 agent」的工厂
  }
}

所以「循环」并不神秘：它和记忆零件、换 Logo 零件是同一套插件规则，只不过它扮演「发令」的角色。

循环的主体：一段写死的最小状态机

循环内部叫 ReactLoopAgent（刻意不导出，外部只能「整台替换」，不能「拆开改」）。它的核心就是 turn() / step() 两个方法——一段手写、固定的节奏：

// 内核循环的真正节奏（简化到只剩「喊话」和「写日志」）
while (await turn()) {}                    // 一轮接一轮，直到没有待办

async turn() {
  会话日志.append("turn/start");             // ① 开一轮
  while (true) {
    decision = await 接力棒喊("agent/pre-step");  // ② 动脑前：喊，插件可塞小抄
    for (m of decision.messages) 会话日志.append("user/message", m);  // ③ 逐条写进输入
    await step();                          // ④ 真跑一步：调模型 + 跑工具
    if (这轮结束了) 排队喊("agent/turn-stopping");  // ⑤ 收尾：喊，插件可记笔记
  }
  会话日志.append("turn/end");               // ⑥ 关一轮
}

这张「节奏表」就是全部秘密：循环在每个固定节点喊一嗓子，插件就在这些节点介入。

它只干三件事，其余全是插件

循环被刻意压到「不可再省的最小核」——官方自述：调用模型、运行工具、重复。记忆、压缩、重试、沙箱、子代理、持久化、界面……全部是监听上面那些节点的别的插件在干。核心越薄，你介入的点就越清晰、越安全——这正是「易于开发」的根子。

「一切皆自定义」的真实边界

能换的是两侧：电器（具体插件）随便换，甚至电流源（这个内核循环）也能整个换掉。唯一固定的是插座规格——事件名 + 数据袋的形状，这是全生态共享的契约。只要你不去改这个契约，两侧怎么换都能互相兼容。

4.4 灯座：换 Logo 就是这么简单

界面也一样，官方把「品牌 Logo」留成了几个灯座（侧边栏图标、侧边栏字标、对话页角标）。谁往灯座里拧灯泡，谁就亮。于是「把 DeepSeek 的鲸鱼换成部门名 IME」这种需求，不需要动任何核心代码——写一个小零件，往同一个灯座里拧上自己的灯泡就行：

// dsh-ime-brand：把官方鲸鱼 Logo 换成部门字标 "IME"
function apply(ctx) {
  ctx.slots.register({ name: "sidebar.brand.mark" }, () => ImeMark());  // 图标 → IME
  ctx.slots.register({ name: "sidebar.brand.name" }, () => ImeWordmark());  // 字标 → IME
}

说明：官方自带的品牌零件，就是用这同一组灯座渲染 DeepSeek 鲸鱼；你的零件占用同一灯座，就把它「顶掉」了。

5改「能力」 vs 改「长相」：同一套插头

我们做了两个零件，一硬一软，正好说明「一切皆插件」的覆盖面：

零件 A：记忆（dsh-memory）零件 B：IME 换 Logo
它改了什么AI 的能力——能不能记住事AI 的长相——界面叫什么名
接在哪供电（提供记忆本子）+ 通电（动脑前、一轮结束两个时机）灯座（侧边栏图标 / 字标）
不碰什么不改 AI 本身、不改主循环不改模型、不改任何逻辑
代码量一个中等大小的零件，内部还能再换（换存储、换搜索方式）约 10 行
两个零件摆在一起看

一个深入主干（改 AI 能做什么、记得什么），一个只贴表面（改 AI 长什么样）。但它们是同一套插头、同一种「零件」的写法。这就是「一切皆插件」真正厉害的地方：从记忆到 Logo，全在同一个插座体系里。

6对我们的意义：为什么它适合二次开发

🧩

一切可自定义

界面、工具、记忆、模型、沙箱……要什么插什么，不用的拔掉。

🔁

热插拔、可回滚

换零件不用重装系统；换错了还能完整还原（「拔得干净」兜底）。

🚫

永远不碰核心

二次开发永远在「写零件」，不动底座源码，系统升级也不怕自己的改动作废。

👥

分工友好

开发造「能力零件」，业务提需求点零件；甚至能让 AI 自己给自己装零件。

也要说清楚：代价是什么

代价说明
上手门槛高要理解「零件、插座、时机」这套思路，比开箱即用的工具陡。
出了事更难排查行为是几十个零件「拼」出来的，要顺着「谁挂了哪个时机」去查。
仍是预览版才 v0.1，官方明说未来可能有不兼容的改动，上生产要评估。

但这些代价，换来的正是我们想要的：一个能随部门需求持续长、而不是「买来就用、用不了就换」的底座。

7方法论启示：先做「工具」和「数据」，再长整体

这是最想留给团队的一条建议，尤其对还没想清楚「整体长什么样」的项目：

没想清楚整体时，先做「最小、最独立」的零件

在 Harness 里，「工具」（AI 能做什么）和「数据」（AI 记得什么），恰好是两块最小、最独立、几乎一定用得上的零件。它们不依赖你还没想清楚的「整体架构」。先把它们做扎实，整体以后再拼——因为在这里，后面随时能把它们重新拼进任何更大的结构里，不用返工。

我们的「记忆」零件就是这套思路的活样板：它没有一开始就纠结「要不要向量库、要不要审批流」，而是先把「记住 + 召回 + 遗忘」这个核心做扎实（存个本地文件、简单搜一下），同时留好可换的口子——存哪、怎么搜、怎么显示，以后都能换。要升级，是「拧开一颗螺丝换零件」，不是「推倒重来」。

1
先做「工具」（能做什么）把一个个能力做成独立零件：查数据、发审批、读文件…… 每个都能单独用、单独试。
2
再做「数据」（记得什么）把要长期存的东西做成带可换存储的零件，先从一个本地文件起步。
3
用「时机」把它们串起来在「动脑前」「一轮结束」这些插座上接线，让零件开始自动配合。
4
整体长出来流程、界面、主循环的替换…… 等看清了再补，之前做的零件一块都不浪费。

别等完美蓝图。先把「工具 + 数据」两块最小零件打磨好，保持接口可替换，系统就天然有了持续迭代的能力——这就是 Harness 这块「万能插座」最大的红利。

8总结

DeepSeek Harness 是一块 给 AI 用的万能插座：没有焊死的部分，一切皆插件；零件靠 供电、通电、灯座 三个接口接进去，所以适合二次开发、一切可自定义。对我们最实在的启示是——先把「工具」和「数据」两块最小零件做扎实，整体边做边长。

建议的下一步

① 装一个 Harness（npx @deepseek-ai/dsh web），在设置页看看 200 多个零件是怎么拼成一台 AI 的；② 照「记忆」零件抄一个最小的（哪怕只做一个工具），亲手「插一次插头」；③ 想清楚我们要做的第一个「工具」或「数据」是什么。
