外置智能体记忆：何时触发、如何召回

Hermes Agent（Nous Research）记忆架构 × 主流外置记忆方案 · 一页报告 · 2026-09-08
官方文档 + 学术论文 + 本地源码（hermes-agent/ @ 本仓库）三重交叉验证

0 · 纠偏：Hermes 内置记忆不用向量库

L1 是两个 Markdown 文件（MEMORY.md ≤2200 / USER.md ≤1375 字符，tools/memory_tool.py:924）；L2 会话搜索是 SQLite FTS5 全文索引（unicode61 + CJK trigram，hermes_state_common.py:661），BM25 取 top-3 会话 + 辅助 LLM 摘要"软重排"，官方概括 "SQLite FTS5 + LLM 摘要 + 文件级持久化" [1][2][3]。 向量库是外挂的：plugins/memory/ 下 8 个记忆提供者（mem0、supermemory、retaindb、hindsight、honcho、openviking、byterover、holographic），MemoryManager 强制同时仅激活一个，与内置记忆并行、写入自动镜像 [1][2]。

1 · Hermes 记忆栈（L0–L2）

层存储形态触发与召回
L0系统提示词内的冻结快照会话开始一次装配（保 KV 缓存），常驻上下文、无检索
L1MEMORY.md/USER.md（原子写+注入扫描）Agent 经 memory_tool 自主编辑立即落盘；下次会话全量注入、不检索
L1.5各提供者后端（向量库/图/云）每轮前 prefetch 预取注入 + Agent 主动调搜索工具（见下方时序）
L2SQLite WAL + 双 FTS5 虚拟表（触发器同步，含工具调用参数）按需：FTS5 MATCH + BM25 → 排除谱系 → top-3 会话 → LLM 摘要软重排 [2][3]

2 · 主流外置记忆系统：触发时机与召回算法

范式系统存储形态写入何时触发召回何时触发 · 算法
AMemGPT / Letta [4][5]main context（窗口内）+ external context：recall 存储（历史）+ archival（向量库）Agent 自主：函数调用自写记忆；上下文 FIFO 溢出时系统自动递归摘要旧消息压入 recall 存储Agentic 按需：LLM 自主调用 archival_memory_search / conversation_search；archival 语义向量检索、不能常驻；core memory 常驻可自编辑
BMem0 [6]向量库（dense embeddings；图变体 Mem0g）每轮自动两阶段：抽取（结合最近 m=10 条消息抽候选事实）→ 更新（向量检索 top-s=10 相似旧记忆，LLM tool-call 判定 ADD / UPDATE / DELETE / NOOP）每次查询自动：问题嵌入 → 向量库相似度 top-k（可选 LLM 重排）→ 注入提示词
BZep / Graphiti [7]Neo4j 时序知识图谱（双时间轴：事件 vs 摄取；矛盾边自动失效）每条消息一个 Episode 摄取：结合最近 n=4 条消息抽取实体/事实边，带参考时间戳每次查询自动：余弦语义 + BM25 全文（Lucene）+ BFS 图遍历（最近 Episode 作种子）→ RRF / MMR / 交叉编码器重排 → top 边+节点（实验取 20 条边）
CGenerative Agents（经典基线） [8]记忆流（事件流 + 嵌入向量）每个观察/行动即时写入记忆流每个决策点（规划/反应/对话/反思）：score = α·recency + α·importance + α·relevance（α 全 1；recency=指数衰减 0.995/小时；importance=LLM 1–10；relevance=嵌入余弦；min-max 归一）取 top-k

范式 A＝LLM 自主工具调用（省 token、依赖模型自觉）；B＝托管自动管线（每轮写 + 每查询检索，稳定但有固定开销）；C＝决策点全量检索 + 三因子排序。

3 · Hermes 外部提供者共享触发时序 [1][2]

① 会话开始
system_prompt_block() 提供者上下文注入系统提示词
→
② 每轮之前
prefetch(query) 后台非阻塞预取，以 <memory-context> 注入本轮用户消息
→
③ 每轮之后
sync_turn(user,asst) 异步写入对话轮（部分提供者增量抽取）
→
④ 会话末 / 压缩前
on_session_end / on_pre_compress 整段会话抽取为长期记忆

提供者触发差异：Supermemory 每轮前 auto_recall / 每轮后 auto_capture / 每 50 轮更新 profile；Hindsight 用 auto_retain/auto_recall 开关；ByteRover 在压缩前抽取；Holographic 会话末 auto_extract 默认关；OpenViking 在 session commit 分 6 类抽取 [1]。

结论："最主流"是一个谱系——越靠 LLM 自觉（范式 A）召回越省但可能漏；越靠自动管线（范式 B）召回越稳但有固定开销。工业界当前收敛在范式 B（Mem0/Zep 式"每轮自动写 + 每查询自动混合检索"，Hermes 外部提供者也走这条时序）；召回排序底座默认仍是 Generative Agents 三因子 [1][6][7][8]。Hermes 内置栈是成本优先的反例：FTS5 关键词召回 + LLM 摘要重排替代向量检索，语义泛化推迟到摘要阶段 [2][3]。
